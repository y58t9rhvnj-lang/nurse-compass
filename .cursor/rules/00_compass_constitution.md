# Compass Constitution（最上位）

Compass Version2.1 以降の開発における**最優先ルール**。  
設計・実装・レビューで迷った場合は、この文書を基準に判断する。

## Mission

Compass は電子カルテでも、看護記録ソフトでもない。  
**「患者理解を育てる Learning Workspace」** である。  
すべての設計・実装・UI・UX はこの Mission のために行う。

## 13原則

1. **入力システムではなく Learning Workspace** — 入力効率より、考えながら患者理解を深める体験を最優先する。
2. **主役は患者** — 画面の主役は AI でも様式でもない。常に患者を中心に設計する。
3. **一度に考えることは一つ** — 1つの健康パターンに集中できる UI。11パターン同時入力は避ける。
4. **情報は転記しない** — 様式2は様式3へコピーしない。手がかりとして参照し、学生自身が再整理・再解釈する。自動転記は実装しない。
5. **Guide は答えを書かない** — 定義・情報収集の視点・考えるためのヒントのみ。看護問題や解釈の答えは提示しない。
6. **Compass Coach は問いを返す** — 学生の代わりに考えない。気付き・根拠確認・視点拡大の質問を返す。
7. **入力順序は思考順序** — 様式3は必ず「関連情報 → 解釈 → 判断 → 根拠 → 必要な追加情報」の順。
8. **保存を意識させない** — オートセーブを基本。保存ボタンのために思考を止めさせない。
9. **iPad First** — 最優先は講義中の iPad Safari。PC はその次。
10. **色には意味を持たせる** — 装飾ではなく状態理解のためだけに使う（緑=正常 / 青=強み / 赤=問題 / オレンジ=リスク / グレー=情報不足）。
11. **未完成を肯定する** — 途中の思考や迷いも学習の一部。途中保存・途中修正を前提にする。
12. **Compass は Learning Workspace** — 迷ったら「この機能は患者理解を深めるか」を最優先の判断基準にする。
13. **思考は見える化するが、自動化しない** — AI は看護問題を決定しない・関連図を完成させない・正解を提示しない。「思考を代替するAI」ではなく「思考を深めるAI」。

## 実装時の確認（必須）

1. Compass Constitution に反していないか。
2. Learning Workspace として価値があるか。
3. 学生自身の思考を奪っていないか。
4. 患者理解を深める体験になっているか。

反する場合は実装を止め、理由と代替案を提示する。
