# Compass Product Blueprint

**Compass Version3 — 製品の設計思想を共有するための文書**

- 読者: 教員・学校関係者・プロダクト・開発・AI設計に関わるすべての人
- 性質: 技術仕様書ではない。Compass が「何のために在るか」を共有する
- 根拠: Core Design Freeze v1（`fb0d990`）および Artifact Model（`07_artifact_model.md`）
- ブランチ: `feature/version2-form3`

---

## 1. ひとことで言うと

**Compass は、看護学生が「患者さんを理解する力」を育てるための学習の場です。**

様式を埋めるためのシステムではありません。  
電子カルテの代わりでもありません。  
AI が正解の看護問題を出すツールでもありません。

学生が事実を集め、考え、関係づけ、その結果として学校の様式にまとめられる——その過程を支える製品です。

---

## 2. なぜ Compass が必要か

看護教育では、しばしば次のことが同時に求められます。

- 患者さんを深く理解すること  
- アセスメントし、優先順位を考え、看護問題や計画につなげること  
- 学校指定の様式（様式2・様式3など）に、決められた形で書くこと  

現場では、どうしても **「まず様式を埋めなければ」** が前面に出やすくなります。  
その結果、事実と解釈が混ざり、根拠のない断定が増え、関連図や看護問題が「あとから当てはめる作業」になりがちです。

Compass が目指すのは、その順序を戻すことです。

> **先に患者理解と臨床推論。様式はその結果。**

学校の様式そのものは変えません。  
変えるのは、様式に向かうまでの **考え方の道筋** です。

---

## 3. Compass が約束すること／しないこと

### 3.1 約束すること

| 約束 | 意味 |
| --- | --- |
| 患者が主役 | 画面の中心は様式ではなく、受け持ちの患者さん |
| 事実と考えを分ける | 「何が分かったか」と「どう考えたか」を混ぜない |
| 途中の思考を尊重する | 未完成・迷い・修正も学習として扱う |
| 学校様式を守る | 指定された項目名・順序・意味は変更しない |
| 教員の形成的支援を支える | 順位付けや自動採点ではなく、対話と振り返り |

### 3.2 しないこと

| しないこと | 理由 |
| --- | --- |
| 様式の自動完成 | 書くこと自体が学びだから |
| 様式2から様式3への自動転記 | 再整理・再思考を奪うから |
| AI による正解アセスメント／看護問題の提示 | 学生の推論を代替してしまうから |
| 患者理解の点数化・順位付け | 選別ではなく育成が目的だから |
| 学校指定様式の改変 | 学校の共通言語を壊さないため |

---

## 4. 製品の骨格（だれでも追える5つの段）

Compass の学びは、次の流れで整理されます。  
行き来は許しますが、「様式だけ先に埋める」はしません。

```
① 患者（Patient）
    「だれについて考えるか」
        ↓
② 情報（Information）
    「何が事実として分かっているか」
        ↓
③ アセスメント（Assessment）
    「その事実から、自分はどう考えるか」
        ↓
④ 臨床推論ネットワーク（Clinical Reasoning）
    「考え同士はどうつながるか」
        ↓
⑤ 成果物（Artifacts）
    「学校の様式・看護問題・計画などにどうまとめるか」
```

### かんたんに言うと

| 段 | 学生の問い | 大事なルール |
| --- | --- | --- |
| 患者 | だれを受け持っているか | 教材ケースとして扱う |
| 情報 | 何が起きている／言われているか | **解釈を書かない**（1事実ずつ） |
| アセスメント | それは自分にとって何を意味するか | **正解ではない**。根拠となる情報を持つ |
| 臨床推論 | どの考えが関係しているか | 関連図の「見た目」ではなく、**関係そのもの** |
| 成果物 | 学校にどう提出するか | **自分の言葉で統合**する。自動生成しない |

教員・学校の方へ:  
この5段は「評価ルーブリックの5項目」ではありません。  
**学習の順番と役割分担**です。成果物の良し悪しだけで、途中の思考を切り捨てないための設計です。

---

## 5. 学習フロー（学生の一日のイメージ）

1. **患者さんを見る**  
   カルテ・会話・検査などの一次情報に触れる。

2. **事実を切り出す**  
   「食欲低下」「SpO₂ 91%」のように、解釈を混ぜず情報カードにする。

3. **考えて言語化する**  
   「低栄養が疑われる」「転倒リスクがある」など、1つの考えにつき1つのアセスメントにする。  
   正常・強み・問題・リスク・情報不足が、同時にあってよい。

4. **関係づける**  
   考えと事実のつながりをネットワークとして整理する。  
   （画面上の関連図は、その関係を見る・触るための道具です。）

5. **学校の様式にまとめる**  
   様式3の提出欄、看護問題、計画、振り返りなどは、ここまでの理解を **自分で** 書く。  
   Compass は下書きや参照を助けても、文章を自動では埋めません。

6. **提出する**  
   提出した時点の内容は固定され、あとから「そのとき何を提出したか」を説明できます。  
   提出後も、学習としての再考は続けられます。

---

## 6. 創発（Emergence）— 看護問題は「最初に決めるもの」ではない

Compass では、次のものを **最初から入力させる目標** にしません。

- 看護問題  
- 優先順位（提出用）  
- 看護計画  
- 様式3の完成文  
- 提出用の関連図  

これらは、情報・アセスメント・関係づけが十分に育ったとき、**自然に見えてくる結果**として扱います。

だから Compass は「看護問題を書くアプリ」ではありません。  
**看護問題が見えてくるまで、患者理解を支えるアプリ**です。

---

## 7. ワークスペースと成果物

現場で混同しやすいので、言葉を分けます。

| | Learning Workspace（考える場） | Artifact（出すもの） |
| --- | --- | --- |
| 目的 | 事実と考えを整理する | 学校の形式で提出・共有する |
| 例 | 情報カード、アセスメントカード、関係づけ | 様式2・様式3の提出欄、看護問題、計画、振り返り |
| ルール | 原子的に、根拠を持って考える | 学校指定の欄は変えない |

様式3では特に、次を分けます。

- **考える画面（Workspace）** … カードで事実と解釈を整理  
- **提出の様式（Final）** … 学校指定の欄へ、学生が自分の言葉でまとめる  

カードの内容を、様式へ自動で流し込むことはしません。

---

## 8. AI（Compass Coach）の役割

AI は **答えを出す先生役**ではありません。  
**問い返す伴走者（Coach）**です。

### してよいこと

- 「このアセスメントの根拠は足りていますか？」  
- 「この情報から、別の解釈はありますか？」  
- 「つながっていない事実や、孤立した考えはありませんか？」  

### してはいけないこと

- 正解のアセスメントや看護問題を提示する  
- 様式の文章を学生の代わりに完成させる  
- 患者理解を点数化して順位をつける  

教員の役割は残り続けます。  
AI は、教員の問いかけをすべて置き換えるものではなく、学生が一人で考える時間の質を上げるための補助です。

---

## 9. だれに、どんな価値があるか

### 学生

- 様式の圧に潰されず、患者さんから考えられる  
- 事実と考えの区別が身につく  
- 途中の思考が残り、あとから振り返れる  
- 提出物は「写しただけ」ではなく、自分の統合になる  

### 教員

- 完成文だけでなく、根拠と解釈の過程を見られる  
- 形成的なフィードバックの材料が増える  
- 学校様式はそのまま使える  
- 「転記作業の指導」から「推論の指導」へ重心を移せる  

### 学校・教育機関

- 指定様式・教育方針を壊さない  
- Clinical Reasoning 教育の共通言語を持てる  
- 将来の関連図・看護問題・計画・振り返りを、同じ思想の上に載せられる  

### 開発・プロダクト

- 「便利な自動入力」より「学習過程を守る」が判断基準になる  
- Core（考える骨格）と Module（様式・画面）を混ぜない  

---

## 10. 成功の見え方（KPI ではなく、観察の目安）

数値ランキングは使いません。代わりに、現場で次を観察します。

- 学生が様式の前に、事実カードとアセスメントを書けているか  
- 根拠のない断定が減っているか  
- 情報不足を「不足」として保留できているか  
- 看護問題や様式文が、関係づけのあとに出てきているか  
- 教員が「答え合わせ」より「なぜそう考えたか」を話せているか  

---

## 11. Version3 で大切にしている原則（共有用）

1. **Single Source of Truth** — 同じ意味をあちこちにコピーしない（事実は情報、考えはアセスメント、関係は推論、提出は成果物）  
2. **1カード1事実／1カード1解釈** — 小さく分け、あとで関係づける  
3. **Modules は Core の上に乗る** — 画面や様式が、考える骨格を上書きしない  
4. **提出は Snapshot** — 出した時点の表現は固定する。学習の再考は止めない  
5. **学校様式は不変** — Compass は様式を守る側に立つ  

---

## 12. よくある誤解

| 誤解 | 実際 |
| --- | --- |
| Compass＝記録ソフト | 記録ではなく、臨床推論の学習基盤 |
| Compass＝様式入力支援 | 様式は最後。先に理解と推論 |
| 関連図＝臨床推論そのもの | 関連図は見せ方。中身は関係のネットワーク |
| アセスメント＝看護問題 | アセスメントは途中の考え。看護問題は提出用の成果物 |
| AI が採点する | AI は問い返す。採点・順位付けはしない |

---

## 13. これから先（製品としての道筋・概観）

技術詳細は別文書に任せ、製品として見える順番だけ示します。

1. **考える骨格（Core）を共有する** … いまここまで設計済み  
2. **成果物の扱いを明確にする** … 様式・振り返り・提出の考え方（Artifact）  
3. **画面と機能を骨格に合わせて育てる** … 様式3ワークスペース、関連図、Coach など  
4. **学校導入では様式を守ったまま、学習過程を厚くする**  

既存の Version2 の学びは壊さず、段階的にこの思想へ寄せます。

---

## 14. 一文のミッション

> **Compass は、看護学生が患者さんについて考え続けられるようにし、  
> その結果として、学校が求める成果物を自分の言葉で生み出せるようにする。**

様式のためではなく、患者理解のために。  
正解を渡すためではなく、問いと根拠のある思考のために。
