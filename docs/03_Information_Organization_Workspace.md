## 1. 教育思想（Educational Philosophy）

Compass は「学生が情報を集めること」を助けるための道具ではない。
Compass は「学生が情報を整理し、患者を理解すること」を助けるための道具である。

```
情報収集は始まりにすぎない。
学びは、整理の過程で起こる。
```

情報を集めただけでは理解は生まれない。
集めた情報を、学生自身が並べ替え、比べ、意味を考える——
その**整理の過程**こそが Compass の学習の中心である。

---

## 2. 3段階の学習モデル（Three-Stage Learning Model）

Compass は学習を、明確に区別された3つの段階として設計する。

### Stage 1 — 情報収集（Information Collection）

出所の例：

- 患者との対話
- 電子カルテ
- 看護記録
- フローシート
- 処方
- 学生の観察

性質：

- 自由に集めてよい
- **重複してよい**
- 原文（原記録・患者の言葉）を保持する
- 事実は編集しない

Stage 1 で扱うのは「証拠（evidence）」であり、まだ解釈ではない。

### Stage 2 — 情報整理ワークスペース（Information Organization Workspace）

性質：

- 学生が、集めた情報を整理する
- 自分の言葉に書き換える
- 重複をまとめる
- 関連する情報をグループ化する
- 新たな理解を書き加える
- 不要な情報を取り除く
- 臨床的に意味のある情報を組み立てる

**これが Compass の中核となる教育ワークスペースである。**

### Stage 3 — 表現（Expression）

例：

- 様式2
- 様式3
- 患者関連図

学生は、整理した情報を選び取り、自分の理解を表現する。

## 3. データ → 情報 → 手がかり モデル（Data → Information → Cue）

Compass Version1 の情報整理モデルとして、次の3段階を定義する。
この3段階は、§2 の学習モデルおよび「証拠 → 整理 → 表現」（§6）と対応する。

| 段階 | 用語 | 対応する Stage | 主体 |
|------|------|----------------|------|
| 事実 | データ（Data） | Stage 1 収集 | 患者・カルテ・観察（出所） |
| 意味づけ | 情報（Information） | Stage 2 整理 | 学生 |
| 思考の方向 | 手がかり（Cue） | Stage 2 → 3 の橋渡し | 学生 |

> 本モデルは Version1 時点の**教育設計上の仮説**であり、
> 実装後の学生・教員の使用状況に応じて見直す可能性がある（§3.8 参照）。

### 3.1 データ（Data）

患者との会話・観察・電子カルテ等から得られた、
**まだ学生による意味づけをしていない事実**。

例：

- 「夜中に何度も目が覚める」
- 睡眠時間4時間
- 食事摂取量6割
- 表情が硬い
- 「母が心配」

原文・数値・出典を保持し、内容を書き換えない。

> 実装対応：システム内部の型名 `InformationCard`（`lib/information/`）は保持するが、
> 学生向け UI では原則として「**データ**」と表現する。
> ＝カードは Stage 1 の未整理の事実であり、まだ「情報」ではない。

### 3.2 情報（Information）

1つまたは複数のデータを、学生が整理・統合し、
**患者理解に必要な意味を持たせたもの**。

学生は情報整理ノート上で、次のことができる：

- 表現を整える
- 重複をまとめる
- 複数のデータを統合する
- 必要な内容を追記する
- 不要な内容を整理する

情報は学生が作成する。
**Compass が自動的に文章化・要約してはならない。**

### 3.3 手がかり（Cue）

整理した情報をもとに、

- 次に何を考えるか
- 何を追加確認するか
- どの関係に着目するか

を示す**思考の方向**。

手がかりは、答えや看護問題の確定ではない。

例：

```
情報：夜間覚醒が継続している
手がかり：
  - 不安との関連はないか
  - 服薬の影響はないか
  - 日中生活へどう影響しているか
```

### 3.4 学習の流れ

```
患者との対話・観察・カルテ
   ↓
データを収集
   ↓
情報整理ノートで情報へ整理
   ↓
情報から手がかりを見いだす
   ↓
様式2
   ↓
様式3
   ↓
病態関連図を参照
   ↓
患者関連図
   ↓
看護問題がなぜ生じているかを説明する
```

各段階を意図的に分離する理由：

- データと解釈を混同しない
- 学生自身の意味づけを守る
- 思考の過程を振り返れる
- 出典（データの出所）へ戻れる

### 3.5 重複データの扱い

収集段階では重複を許容する。

例：

- 患者：「夜中に目が覚める」
- 診療録：夜間覚醒あり
- フローシート：睡眠4時間
- 学生観察：日中眠そう

情報整理ノートで学生が選択する：

- そのまま残す
- 統合する
- 不要と判断する
- 別の意味を持つデータとして分ける

**元のデータは削除・上書きしない。**
整理後の情報から、元データとその出典を参照できる設計とする
（§7 重複の扱い・`docs/02_Information_Card_Model.md` 原則2・5 と一致）。

### 3.6 様式2・様式3との関係（将来仕様）

様式2・様式3では、次を将来仕様とする：

- 情報整理ノートの情報を引用できる
- 必要に応じて直接入力もできる
- 引用元のデータと出典を確認できる

様式3の列との関係（対応の目安）：

```
情報（S・O）    … 出所を保持したデータ／整理した情報
解釈・分析      … 情報から学生が考えた意味
診断の手がかり  … 手がかり（Cue）に対応しうる
```

ただし、「データ・情報・手がかり」と学校様式の各列を
**機械的に完全一致させない。**
学校教育上の実際の使われ方を検証しながら調整する
（`docs/01_Compass_Version1_Spec.md` 3.5 と一致）。

### 3.7 このモデルにおける AI / Coach の役割

Compass Coach ができること：

- 別の視点を問いかける
- 比較を促す
- 不足情報への気づきを促す
- 学生の考えを言語化する問いを返す

Compass Coach が行わないこと：

- データを自動的に情報へ変換する
- 情報整理文を自動作成する
- 手がかりを正解として提示する
- アセスメントを完成させる
- 看護問題を決定する

（§8 AI の役割・`docs/00_Compass_Charter.md` §3 Coach 原則と一致。）

### 3.8 本モデルは教育仮説である

「データ → 情報 → 手がかり」という構造は、
Compass Version1 における**教育設計上の仮説**である。

実装後に、次を検証する：

- 学生が理解しやすいか
- 教員が指導しやすいか
- 学校の様式と自然につながるか
- 用語が臨床・看護教育上適切か

検証結果に応じて、名称・区分・操作を変更しうる。
ただし変更は、本書の理念（証拠の保持・学生の意味づけ・思考の分離）を
守るための改善に限る。

## 4. 情報カードの思想（Information Card Philosophy）

情報カードは**証拠（evidence）**である。
情報カードは、学生の解釈ではない。
（本書 §3 の用語体系では、情報カードは「**データ**」にあたる。）

例：

```
患者：「夜中に何度も目が覚めるんです。」
カルテ：夜間覚醒あり。
観察：日中に眠そうにしている。
```

これらはそのまま保持される。

```
情報カードは、決して書き換えない。
```

カードは Stage 1 の証拠として不変であり、
学生の言葉への変換や統合は、次の Stage 2（情報整理ノート）で行う
（詳細は `docs/02_Information_Card_Model.md` の原則2・5と一致）。

---

## 5. 情報整理ノート（Information Organization Notebook）

情報整理ノートを、次のように定義する。

```
集めた証拠を、整理された臨床的理解へと、
学生自身が変換していく作業台。
```

学生は、ノートの中で次のことができる：

- 書き換える（rewrite）
- まとめる（merge）
- 分ける（split）
- 分類する（classify）
- 要約する（summarize）
- 情報同士をつなぐ（connect）

```
ノートは、学生のものである。
```

Compass は、ノートを自動で書き換えたり、要約したりしない。
整理の主体は、あくまで学生である。

> 実装上の注意：現行の「気づきメモ」（`lib/notes.ts` / NoteZone）は
> 情報整理ノートの前身にあたる。Sprint11.1 で導入した情報カード基盤
> （`lib/information/`）とは独立しており、自動同期・自動転記は行わない。

---

## 6. 証拠と解釈の関係（Evidence and Interpretation）

Compass は、次の3段階を**意図的に分離する**。

```
証拠（Evidence）
   ↓
整理（Organization）
   ↓
表現（Expression）
```

- **証拠**は保持され、書き換えられない（Stage 1 / 情報カード）。
- **整理**は学生が行い、証拠から理解を組み立てる（Stage 2 / 情報整理ノート）。
- **表現**は整理された理解を選び取って示す（Stage 3 / 様式・関連図）。

この分離は偶然ではなく、Compass の設計意図である。
証拠と解釈を混ぜないことで、「何が事実で、何が自分の考えか」を
学生が常に区別できるようにする。

---

## 7. 重複の扱い（Duplicate Handling）

収集（Stage 1）の段階では、重複は許容される。

整理（Stage 2）の段階で、学生が判断する：

- 残す（keep）
- まとめる（merge）
- 捨てる（discard）

```
この判断の過程そのものが、教育である。
```

Compass が自動で重複を削除・統合してはならない。
「どれを残し、どれをまとめ、どれを捨てるか」を学生が決めることに、
学びがある。

---

## 8. AI の役割（Role of AI）

Compass の AI は、学生の整理を代わりに書いてはならない。

Compass AI がしてよいこと：

- 別の視点を示唆する
- 比較を促す
- 不足している情報を思い出させる

Compass AI がしてはならないこと：

- ノートを書き換える
- 自動で要約する
- 重要度を判断する
- アセスメントを生成する

この役割は、Charter の原則（§2.3「答えを与えない」・§2.6「一般知識と個別患者の
接続は学生が行う」・§2.7「学生の思考時間を奪わない」）と一致する。

## 9. 将来のワークフロー（Future Workflow）

Compass Version1 の将来のワークフローは、次の一続きの導線として構成される。

```
患者
   ↓
電子カルテ
   ↓
メモ／情報収集（Information Collection）
   ↓
情報整理ノート（Information Organization Notebook）
   ↓
様式2
   ↓
様式3
   ↓
病態関連図の参照（Pathophysiology Reference）
   ↓
患者関連図（Patient Relationship Diagram）
   ↓
看護問題が「なぜ生じているか」の理解
```

今後実装するすべての画面は、このワークフローに従う。
各画面は「次に何を考えるか」を支援し、情報カードを共通の通貨として
段階間を受け渡す（`docs/01_Compass_Version1_Spec.md` と一致）。

## 10. 設計原則（Design Principles）

- **証拠は保持される。**（Evidence is preserved.）
- **理解は学生のものである。**（Understanding belongs to the student.）
- **整理こそが学びの場である。**（Organization is where learning occurs.）
- **Compass は思考を支えるが、思考を肩代わりしない。**
  （Compass supports thinking without replacing it.）
- **情報整理ノートは、Compass Version1 の教育的中心である。**
  （The Information Organization Notebook is the educational center of Compass Version1.）
