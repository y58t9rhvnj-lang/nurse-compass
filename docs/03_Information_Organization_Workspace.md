## 1. 教育思想（Educational Philosophy）

Compass は「学生が情報を集めること」を助けるための道具ではない。
Compass は「学生が情報を整理し、患者を理解すること」を助けるための道具である。

```
情報収集は始まりにすぎない。
学びは、整理の過程で起こる。
```

情報を集めただけでは理解は生まれない。
集めた情報を、学生自身が並べ替え、比べ、意味を考える——
その**整理の過程**こそが Compass の学習の中心である。

---

## 2. 3段階の学習モデル（Three-Stage Learning Model）

Compass は学習を、明確に区別された3つの段階として設計する。

### Stage 1 — 情報収集（Information Collection）

出所の例：

- 患者との対話
- 電子カルテ
- 看護記録
- フローシート
- 処方
- 学生の観察

性質：

- 自由に集めてよい
- **重複してよい**
- 原文（原記録・患者の言葉）を保持する
- 事実は編集しない

Stage 1 で扱うのは「証拠（evidence）」であり、まだ解釈ではない。

### Stage 2 — 情報整理ワークスペース（Information Organization Workspace）

性質：

- 学生が、集めた情報を整理する
- 自分の言葉に書き換える
- 重複をまとめる
- 関連する情報をグループ化する
- 新たな理解を書き加える
- 不要な情報を取り除く
- 臨床的に意味のある情報を組み立てる

**これが Compass の中核となる教育ワークスペースである。**

### Stage 3 — 表現（Expression）

例：

- 様式2
- 様式3
- 患者関連図

学生は、整理した情報を選び取り、自分の理解を表現する。

## 3. データ → 情報 → 手がかり モデル（Data → Information → Cue）

Compass Version1 の情報整理モデルとして、次の3段階を**正式に確定する**。
この3段階は、§2 の学習モデルおよび「証拠 → 整理 → 表現」（§6）と対応する。

| 段階 | 用語 | 内容 | 対応する Stage | 主体 |
|------|------|------|----------------|------|
| 事実 | データ（Data） | 患者発言・観察・カルテ記載などの事実 | Stage 1 収集 | 出所（患者・カルテ・観察） |
| 整理・分類 | 情報（Information） | データを患者理解のためのテーマ別に整理・分類したまとまり | Stage 2 整理 | 学生 |
| 解釈・方向 | 手がかり（Cue） | 学生が情報を根拠に考えた解釈・関連・追加確認の方向性 | Stage 2 → 3 の橋渡し | 学生 |

**確定における重要点：**

- **情報そのものには、学生の解釈文を含めない。**
- 学生の解釈は「**手がかり（Cue）**」として分離する。
- 情報は「データをテーマ別に整理・分類したまとまり」であり、解釈文ではない。

> 本モデルは Version1 時点の**教育設計上の仮説**である
> （見直し方針は §3.11 を参照）。

### 3.1 データ（Data）

患者との会話・観察・電子カルテ等から得られた**事実**。

例：

- 「薬を飲むと朝起きられないんです」
- 睡眠時間4時間
- 午前中に居眠りがみられる
- 食事摂取量6割
- 表情が硬い

データは次を保持する：

- 原文
- 数値
- 日時
- 出典
- 元情報（出所）への参照

**データ自体は編集・要約・意味づけしない。**

> 実装対応：システム内部の型名 `InformationCard`（`lib/information/`）は保持するが、
> 学生向け UI では原則として「**データ**」と表現する。
> ＝カードは Stage 1 の事実であり、まだ「情報」ではない。

### 3.2 情報（Information）

1つまたは複数のデータを、
**患者理解のためのテーマ別に整理・分類したまとまり**。

複数データの統合は必須ではない。
1つのデータでも、学生がテーマへ配置し、
看護過程で扱いやすい形へ整理すれば「情報」となる。

例：

```
テーマ：睡眠・休息
S情報：「薬を飲むと朝起きられないんです」
O情報：睡眠時間4時間 ／ 午前中に居眠りがみられる
```

この段階では、次のような**解釈文を書かない**：

```
禁止例：「服薬後の眠気により、朝の起床が困難になっている」
```

これは学生の解釈を含むため、情報ではなく「**手がかり**」にあたる。

情報の段階で学生が行うこと：

- テーマ別に整理する
- S情報／O情報／未分類へ分類する
- 並べ替える
- 重複を整理する
- 不要な引用を外す
- 同じデータを複数テーマから参照する

**元データは削除・上書きしない。**

### 3.3 情報の単位（テーマ）

情報の単位は「**患者理解のためのテーマ**」とする。

初期候補：

- 健康管理・治療
- 症状・精神状態
- 睡眠・休息
- 食事・栄養
- 排泄
- 活動・日中の過ごし方
- 服薬
- 対人関係・家族
- 生活歴・役割
- ストレス・対処
- 本人の思い・希望
- その他

ただし、テーマは完全固定しない。学生は将来、次のことができる設計とする：

- 新しいテーマを追加する
- テーマ名を変更する
- 同じデータを複数テーマへ引用する

### 3.4 S・O分類

各テーマ内のデータは、次のいずれかへ分類できる：

- **subjective（主観的データ）** … 患者・家族の発言など
- **objective（客観的データ）** … 観察・測定値・カルテ記載など
- **unclassified（未分類）** … まだ学生が分類していないデータ

S・O分類そのものは**情報整理**であり、**解釈・分析ではない**。

### 3.5 手がかり（Cue）

**手がかり**とは、情報を根拠として学生が考えた、

- 意味・解釈
- 情報同士の関連
- 追加確認すべきこと
- 看護問題を考える方向性

である。

例：

```
根拠となる情報：
  S：「薬を飲むと朝起きられない」
  O：午前中に居眠りがみられる
手がかり：
  「服薬後の眠気が、朝の起床や日中活動へ影響している可能性がある」
```

手がかりは、答えや看護問題の確定ではない。
学生が自由に作成するが、**必ず根拠となる情報・データと結びつける**。

### 3.6 学習の流れ

```
患者との対話・観察・カルテ
   ↓
データを収集
   ↓
情報整理ノートでテーマ別に整理
   ↓
S・O・未分類へ分類
   ↓
情報
   ↓
情報を根拠に学生が手がかりを作る
   ↓
様式2
   ↓
様式3
   ↓
病態関連図を参照
   ↓
患者関連図
   ↓
看護問題がなぜ生じているかを説明する
```

各段階を意図的に分離する理由：

- 事実と解釈を混同しない
- 学生自身の意味づけを守る
- 根拠のない解釈を防ぐ
- 思考の過程を振り返れる
- 出典（データの出所）へ戻れる

### 3.7 重複データの扱い

収集段階では重複を許容する。

情報整理ノートで学生が選択する：

- そのまま残す
- 同じテーマ内で近くに並べる
- 不要な引用を外す
- 別テーマでも使用する
- 異なる意味を持つデータとして分ける

**Compass は自動で統合・削除・要約しない。**
元データは削除・上書きせず、整理後の情報から出典を参照できる設計とする
（§7 重複の扱い・`docs/02_Information_Card_Model.md` 原則2・5 と一致）。

### 3.8 内部モデル（InformationGroup / Cue）

以前検討していた `OrganizedInformation` に **title / content を持たせる構造は採用しない**。

理由：

- 情報は学生の解釈文ではない
- 情報はテーマ別に整理・分類されたデータのまとまりである
- 学生の解釈文は `Cue`（手がかり）として分離する

今後の内部モデルは次を想定する（**設計例。本タスクではコードを実装しない**）：

- `InformationCard` … 収集した事実。学生向け UI では「データ」
- `InformationGroup` … テーマ別に整理されたデータのまとまり。UI ではテーマ名のみ表示
- `Cue` … 学生が情報を根拠に作成した手がかり

```ts
type InformationGroup = {
  id: string;
  patientId: string;
  title: string; // テーマ名（解釈文ではない）
  dataReferences: {
    dataId: string;
    classification: "subjective" | "objective" | "unclassified";
    order: number;
  }[];
  createdAt: string;
  updatedAt: string;
};

type Cue = {
  id: string;
  patientId: string;
  informationGroupId: string;
  content: string; // 学生の解釈・方向性
  evidenceDataIds: string[];
  createdAt: string;
  updatedAt: string;
  createdBy: "student";
};
```

> 実装状況：Sprint11.3A で導入した `lib/organization/`（`OrganizedInformation` に
> title / content を持つ実装）は、本確定より前の暫定基盤である。
> 確定モデルでは、情報は「テーマ別に整理・分類されたデータのまとまり」（`InformationGroup`）とし、
> 学生の解釈文は `Cue` へ分離する。既存の暫定実装は将来の Sprint で
> `InformationGroup` / `Cue` へ再設計する（本タスクではコードを変更しない）。

### 3.9 様式2・様式3との関係（将来仕様）

将来、様式2・様式3では次を可能にする：

- 情報整理ノートの情報を引用できる
- 手がかりを参照できる
- 必要に応じて直接入力できる
- 引用元のデータと出典を確認できる

様式3の列との対応（**参考**）：

```
情報（S・O）    … テーマ別に整理・分類されたデータ（S/O）
解釈・分析      … 手がかり（Cue）に対応しうる
診断の手がかり  … 手がかり（Cue）に対応しうる
```

ただし、Compass の「データ・情報・手がかり」と学校様式の各列を
**機械的に完全一致させない。**
学校での実際の指導方法を検証しながら調整する
（`docs/01_Compass_Version1_Spec.md` 3.5 と一致）。

### 3.10 AI / Coach の役割

Compass Coach ができること：

- 別の視点を問いかける
- S・O の分類を考えるよう促す
- 比較を促す
- 不足情報への気づきを促す
- 根拠を確認する問いを返す

Compass Coach が行わないこと：

- データを自動分類する
- 情報グループを自動作成する
- 手がかりを自動生成する
- 解釈文を自動作成する
- 看護問題を決定する
- アセスメントを完成させる

（§8 AI の役割・`docs/00_Compass_Charter.md` §3 Coach 原則と一致。）

### 3.11 本モデルは教育仮説である

「データ → 情報 → 手がかり」という構造は、
Compass Version1 における**教育設計上の仮説**である。

実装後に、次を検証する：

- 学生が理解しやすいか
- 教員が指導しやすいか
- S・O 分類が学習を助けるか
- 学校の様式と自然につながるか
- 「情報」「手がかり」という名称が適切か
- 実習の思考過程と一致しているか

検証結果に応じて、名称・分類・操作を見直しうる。
ただし変更は、本書の理念（証拠の保持・事実と解釈の分離・学生の意味づけ）を
守るための改善に限る。

## 4. 情報カードの思想（Information Card Philosophy）

情報カードは**証拠（evidence）**である。
情報カードは、学生の解釈ではない。
（本書 §3 の用語体系では、情報カードは「**データ**」にあたる。）

例：

```
患者：「夜中に何度も目が覚めるんです。」
カルテ：夜間覚醒あり。
観察：日中に眠そうにしている。
```

これらはそのまま保持される。

```
情報カードは、決して書き換えない。
```

カードは Stage 1 の証拠として不変であり、
学生の言葉への変換や統合は、次の Stage 2（情報整理ノート）で行う
（詳細は `docs/02_Information_Card_Model.md` の原則2・5と一致）。

## 5. 情報整理ノート（Information Organization Notebook）

情報整理ノートを、次のように定義する。

```
集めた証拠を、整理された臨床的理解へと、
学生自身が変換していく作業台。
```

学生は、ノートの中で次のことができる：

- 書き換える（rewrite）
- まとめる（merge）
- 分ける（split）
- 分類する（classify）
- 要約する（summarize）
- 情報同士をつなぐ（connect）

```
ノートは、学生のものである。
```

Compass は、ノートを自動で書き換えたり、要約したりしない。
整理の主体は、あくまで学生である。

> 実装上の注意：現行の「気づきメモ」（`lib/notes.ts` / NoteZone）は
> 情報整理ノートの前身にあたる。Sprint11.1 で導入した情報カード基盤
> （`lib/information/`）とは独立しており、自動同期・自動転記は行わない。

> 実装対応（確定方針）：学生が作る「情報」は、**テーマ別に整理・分類された
> データのまとまり**（内部型 `InformationGroup`）とし、学生の解釈文は
> `Cue`（手がかり）へ分離する（§3.5 / §3.8 参照）。学生向け UI では
> 情報はテーマ名で表示する。
>
> - 情報・手がかりは**学生だけ**が作成する。Compass は自動生成・自動分類・自動要約しない。
> - 元データ（`InformationCard`）は本文を複製せず、**参照関係**だけで保持する。
> - 1つのデータは複数のテーマから参照でき、1つのテーマは複数のデータを参照できる。
> - 情報・手がかりと参照データの `patientId` は一致していなければならない。
>
> なお、Sprint11.3A で先行導入した `lib/organization/`（`OrganizedInformation` に
> title / content を持つ実装）は本確定より前の**暫定基盤**であり、将来の Sprint で
> `InformationGroup` / `Cue` へ再設計する（本タスクではコードを変更しない）。

## 6. 証拠と解釈の関係（Evidence and Interpretation）

Compass は、次の3段階を**意図的に分離する**。

```
証拠（Evidence）
   ↓
整理（Organization）
   ↓
表現（Expression）
```

- **証拠**は保持され、書き換えられない（Stage 1 / 情報カード）。
- **整理**は学生が行い、証拠から理解を組み立てる（Stage 2 / 情報整理ノート）。
- **表現**は整理された理解を選び取って示す（Stage 3 / 様式・関連図）。

この分離は偶然ではなく、Compass の設計意図である。
証拠と解釈を混ぜないことで、「何が事実で、何が自分の考えか」を
学生が常に区別できるようにする。

---

## 7. 重複の扱い（Duplicate Handling）

収集（Stage 1）の段階では、重複は許容される。

整理（Stage 2）の段階で、学生が判断する：

- 残す（keep）
- まとめる（merge）
- 捨てる（discard）

```
この判断の過程そのものが、教育である。
```

Compass が自動で重複を削除・統合してはならない。
「どれを残し、どれをまとめ、どれを捨てるか」を学生が決めることに、
学びがある。

---

## 8. AI の役割（Role of AI）

Compass の AI は、学生の整理を代わりに書いてはならない。

Compass AI がしてよいこと：

- 別の視点を示唆する
- 比較を促す
- 不足している情報を思い出させる

Compass AI がしてはならないこと：

- ノートを書き換える
- 自動で要約する
- 重要度を判断する
- アセスメントを生成する

この役割は、Charter の原則（§2.3「答えを与えない」・§2.6「一般知識と個別患者の
接続は学生が行う」・§2.7「学生の思考時間を奪わない」）と一致する。

## 9. 将来のワークフロー（Future Workflow）

Compass Version1 の将来のワークフローは、次の一続きの導線として構成される。

```
患者
   ↓
電子カルテ
   ↓
メモ／情報収集（Information Collection）
   ↓
情報整理ノート（Information Organization Notebook）
   ↓
様式2
   ↓
様式3
   ↓
病態関連図の参照（Pathophysiology Reference）
   ↓
患者関連図（Patient Relationship Diagram）
   ↓
看護問題が「なぜ生じているか」の理解
```

今後実装するすべての画面は、このワークフローに従う。
各画面は「次に何を考えるか」を支援し、情報カードを共通の通貨として
段階間を受け渡す（`docs/01_Compass_Version1_Spec.md` と一致）。

## 10. 設計原則（Design Principles）

- **証拠は保持される。**（Evidence is preserved.）
- **理解は学生のものである。**（Understanding belongs to the student.）
- **整理こそが学びの場である。**（Organization is where learning occurs.）
- **Compass は思考を支えるが、思考を肩代わりしない。**
  （Compass supports thinking without replacing it.）
- **情報整理ノートは、Compass Version1 の教育的中心である。**
  （The Information Organization Notebook is the educational center of Compass Version1.）
