# Compass Chart Version1 UI Blueprint

Sprint9（実装前・承認待ち）
対象：精神科電子カルテ「Compass Chart」

---

# 0. 前提となるコンセプト変更

Nurse Compass Version1 は「精神科電子カルテ教材」ではなく、**『精神科病棟実習シミュレーター』の土台**である。

Version1 の核心は、次の往復体験を成立させること。

```
患者と向き合う（Compass Patient）
        ⇅
電子カルテで情報収集（Compass Chart）
```

- **患者画面**：患者紹介ではなく「患者と向き合う場」。表情・姿勢・身の回り・会話が中心。生活歴／家族構成／趣味／価値観は**表示しない**。
- **電子カルテ**：看護過程に必要な情報を収集する場。生活歴・家族・価値観などはすべてここに集約する。
- **Compass Coach**：答えを教えず、問いを返す。

> 本 Blueprint は **Compass Chart（電子カルテ）** の設計に絞る。患者画面側の改修（プロフィール情報の除去）は依存関係として §7 に記載する。

# 1. 画面構成

## 1.1 全体レイアウト（電子カルテ専用モード）

電子カルテを開くと通常の Compass サイドバーは消え、**電子カルテ専用の3カラム**になる（実装済みの方向を継承）。

```
┌────────────┬──────────────────────────────────┬────────────────┐
│ 電子カルテ  │  ① 患者バー（固定ヘッダー）        │  右ペイン       │
│ 専用メニュー │──────────────────────────────────│（補助・控えめ） │
│（左・縦並び）│  ② タブバー（10タブ・横スクロール）│                │
│            │──────────────────────────────────│  Compass Notes │
│ ← Compass  │  ③ タブ本文（情報収集の主役領域）  │                │
│   へ戻る    │                                  │  Compass Coach │
│            │                                  │                │
└────────────┴──────────────────────────────────┴────────────────┘
   ~168px              可変（主役）                    ~240px
```

| 領域 | 役割 | 実装状況 |
|------|------|---------|
| 左：電子カルテ専用メニュー | Alpha 風の機能メニューを Design System で再設計。「← Compassへ戻る」を最上部に | `ChartSideNav`（実装済・継続） |
| ①患者バー | 全タブ共通の固定ヘッダー。患者文脈を失わない | `ChartPatientBar`（実装済・情報拡充） |
| ②タブバー | 10タブの横スクロール・セグメント | `ChartTabs`（実装済・順序確定） |
| ③タブ本文 | 選択タブの情報を密度高く表示 | `ChartMain`＋`ChartTabContent`（全面拡充） |
| 右ペイン | Notes / Coach を控えめに常駐 | `ChartAside`（実装済・継続） |

## 1.2 患者バー（①）の表示項目

Alpha の青い患者ヘッダーに相当。iPad 横で1〜2行に収める。

```
[入院🛏] 患者番号 P-2025-0308 | Aさん  男性 47歳 | 308号室 入院89日目 | 統合失調症 | 主治医 鈴木 | 担当 田中
```

| 項目 | 補足 |
|------|------|
| 入院アイコン | 在院を示すバッジ |
| 患者番号 | P-2025-XXXX |
| 氏名 | 最大サイズ・Bold |
| 性別・年齢 | 補助テキスト |
| 病室・入院日数 | 「308号室 / 入院89日目」 |
| 診断名 | 補助表示（カルテでは明示してよい） |
| 主治医・担当看護師 | Small |

## 1.3 タブバー（②）— 10タブ・確定順

情報収集の思考順序に沿った順序で固定する。

```
患者情報 ▸ 生活歴 ▸ エピソード ▸ 診療録 ▸ 看護記録 ▸ OT ▸ PSW ▸ フローシート ▸ 検査 ▸ 処方
```

- 初期表示タブ：**診療録**（最も「電子カルテらしい」画面で没入感を出す）
- アクティブ：Primary Blue `#0A84FF`／非アクティブ：Warm Gray
- タップ領域：最小 44px 高、横スクロール可

> 補足：タブの並びは「基盤情報（患者情報・生活歴・エピソード）→ 職種記録（診療録・看護記録・OT・PSW）→ 経過・指示（フローシート・検査・処方）」というグルーピング。初期選択のみ診療録。

# 2. 画面遷移

## 2.1 ビュー全体の遷移（AppShell 上位管理）

```
病棟マップ（ward）
   │ 患者をタップ
   ▼
患者と向き合う（patient / Compass Patient）
   │ 「電子カルテを開く」
   ▼
電子カルテ（chart / Compass Chart）
   │ 「← Compassへ戻る」
   ▼
患者と向き合う（patient）
```

- `activeView: "ward" | "patient" | "chart"`（実装済）
- `chart` の時のみ電子カルテ専用レイアウト（通常 SideNav 非表示）
- 「← Compassへ戻る」は**患者画面へ戻る**（往復体験の要）

## 2.2 タブ内遷移

各タブ内での遷移は原則 1 階層に留める（iPad の可読性優先）。

| タブ | タブ内遷移 |
|------|-----------|
| 診療録 | 職種フィルタ（チップ）で一覧を絞り込み。記録は一覧＝詳細を兼ねる（全文表示） |
| フローシート | サブタブ（全体／睡眠・活動／隔離・拘束）＋日付切替 |
| 患者情報 | サブセクションを縦スクロール（タブ内タブは持たない） |
| その他 | 一覧＝詳細（全文カード／表） |

## 2.3 往復導線（Version1 の最重要導線）

```
患者の発言 → [電子カルテを開く] → 該当タブで確認 → [← Compassへ戻る] → さらに質問
                                          ⇅
電子カルテで気づく → [← Compassへ戻る] → 患者へ確認しに行く
```

- 右ペイン Compass Coach が「患者さんへもう一度会いに行きますか？」と往復を促す。
- Version1 では往復は**手動遷移**のみ（自動移動・時間経過なし）。

# 3. 情報設計（タブ別・プレースホルダー禁止）

全タブに実データ（ダミー可）を必ず持たせる。受け持ち3名（A・E・F）は詳細、その他は `wardData` から生成する最小データ。

## 3.1 患者情報
フォーム風グリッド（ラベル＋値）。事務・連絡・入院基盤情報。
- 患者番号／氏名／生年月日／年齢／性別／血液型
- 病室／入院日／入院形態（任意入院 等）／診断名
- 主治医／担当看護師
- 住所／電話／緊急連絡先／キーパーソン
- 職業／保険

## 3.2 生活歴
セクションカードの縦並び（ナラティブ）。
- 生活歴（生い立ち・学歴・職業歴）
- 現病歴（発症〜入院までの経緯）
- 家族背景（家族構成・キーパーソン・関係性）
- 価値観・思い（本人が大切にしていること）
> 患者画面から除いたプロフィール情報の「正式な収集先」。

## 3.3 エピソード
入院・退院・外来・デイケア・訪問看護・再入院などを**時系列テーブル**で。
- 日付／種別（入院・退院・外来 等）／施設／内容

## 3.4 診療録（初期表示・最重要）
白背景1枚に**横罫線区切り**の時系列記録（実装済の方向を継承・拡充）。
- 行：日付／時刻／職種ラベル（医師・看護・OT・PSW 色分け）／記録者／本文
- 上部に**職種フィルタ**（チップ：すべて／医師／看護／OT／PSW／心理）
- 精神科記録らしい自然な文体・十分な記録件数（没入感）

## 3.5 看護記録
テーブル（SOAP／経過）。
- 日付／時間／記録者／観察／対応／評価

## 3.6 OT（作業療法）
テーブル。
- 日付／参加状況／活動内容／集中度／対人交流／スタッフ所見

## 3.7 PSW（精神保健福祉士）
テーブル。
- 日付／家族調整／退院支援／制度利用／地域連携

## 3.8 フローシート
サブタブ＋日別表示（Alpha グリッドを iPad 向けに再設計）。
- サブタブ：全体／睡眠・活動／隔離・拘束
- 日別行：日付・入院日数／睡眠／食事／排泄／活動／服薬／バイタル（T/P/R/BP）

## 3.9 検査
テーブル。
- 検査日／検査名／結果／基準値／コメント（血液・心理検査 等）

## 3.10 処方
テーブル。
- 薬剤名／用量／用法／開始日／注意点（向精神薬中心）

## 3.11 情報設計の共通原則
| 原則 | 内容 |
|------|------|
| プレースホルダー禁止 | 「実装予定」表示は出さない。必ず実データを表示 |
| 情報密度 | 電子カルテらしい密度。大きな余白を減らす |
| 表現の使い分け | 事務＝フォーム、時系列＝罫線リスト／テーブル、ナラティブ＝カード |
| 読み取り専用 | Version1 は閲覧のみ（作成・編集なし） |
| 未入力表現 | データ無しは「未入力」（`#AEAEB5`）で明示 |

# 4. コンポーネント構成

## 4.1 ディレクトリ

```
components/chart/
├─ CompassChart.tsx        中央コンテナ（患者バー＋タブ＋本文）
├─ ChartSideNav.tsx        電子カルテ専用左メニュー（← Compassへ戻る）
├─ ChartPatientBar.tsx     ①患者バー（固定ヘッダー）
├─ ChartTabs.tsx           ②タブバー（10タブ）
├─ ChartMain.tsx           ③本文ディスパッチャ（patientId + activeTab）
├─ ChartTabContent.tsx     タブ別コンテンツの出し分け
├─ ChartUi.tsx             共有プリミティブ（表・フォーム・カード・バッジ）
├─ ChartAside.tsx          右ペイン（Notes + Coach）
├─ ChartNotesPanel.tsx     Compass Notes（控えめ）
└─ ChartCoachPanel.tsx     Compass Coach（控えめ・問いのみ）
```

現状すべて実装済み。Version1 完成に向けた**変更は主に情報の拡充**（`ChartTabContent` と `lib/chartData.ts`）。

## 4.2 新規に必要となる可能性のあるサブコンポーネント（`ChartUi` 内）

| 名前 | 用途 |
|------|------|
| `ChartTable` | 汎用テーブル（既存・継続） |
| `FormGrid` / `FormField` | 患者情報フォーム（既存・継続） |
| `SectionCard` | 生活歴などのナラティブ（既存・継続） |
| `ProfessionBadge` | 職種色バッジ（既存・継続） |
| `FilterChips`（新規） | 診療録の職種フィルタ |
| `FlowsheetTable`（新規/拡張） | フローシートのサブタブ＋日別 |

## 4.3 データ層

```
lib/
├─ chartTabs.ts       ChartTabId 型＋10タブ定義（順序確定）
├─ chartSideMenu.ts   左メニュー項目（既存）
└─ chartData.ts       タブ別・患者別ダミーデータ（A/E/F 詳細＋フォールバック）
```

- `getChartData(patientId)` を単一の入口とする（既存）。
- Version1 完成条件に合わせ、A・E・F の各タブに十分量の記録を追加する。

## 4.4 状態管理

- `activeView`（AppShell）／`activeTab`（CompassChart 内 `useState`）
- `pendingQuestion`（Coach→Notes 誘導、既存）
- 追加状態：診療録の職種フィルタ、フローシートのサブタブ・選択日（各タブ内ローカル `useState`）

# 5. デザイン方針

| 原則 | 適用 |
|------|------|
| Apple HIG | 明確な階層・44px タップ・横スクロールタブ・読みやすい行間 |
| Compass Design System | Warm Gray 背景／白カード／角丸／Line Icon／Very Soft Shadow |
| Alpha 非踏襲 | 色・フォント・Windows 風グリッド・古い装飾はコピーしない |
| 情報密度 | 教材ではなく実習。余白を詰め、電子カルテらしい密度にする |
| 没入感 | 開いた瞬間「本物の電子カルテだ」と感じる（診療録初期表示） |

# 6. Version1 スコープ

## 6.1 実装する
- 電子カルテ専用3カラムレイアウト（実装済の完成）
- 患者バー（情報拡充）
- 10タブ（順序確定・初期＝診療録）
- 全10タブの実データ表示（プレースホルダー全廃）
- 診療録の職種フィルタ
- フローシートのサブタブ＋日別表示
- 右ペイン Notes / Coach（控えめ・継続）
- 患者⇄カルテの手動往復導線

## 6.2 実装しない（Version2以降）
- 患者の自動移動／リアルタイム時間経過／学生アバター
- 記録の作成・編集・削除
- 複雑な AI 会話／AI 関連図／AI アセスメント／AI 要約
- 全文検索・高度フィルタ
- バイタルグラフ・記録間リンク
- バックエンド永続化

# 7. 依存・影響（承認時に合わせて確認したい点）

1. **患者画面の改修**：新コンセプトでは患者画面から生活歴・家族・趣味・価値観を除去し、表情・姿勢・身の回り・会話中心にする必要がある。現状 `CompassPerson` / `CompassStory` はプロフィールを表示している。
   → Compass Chart 実装と同一 Sprint で扱うか、別 Sprint に分けるか要判断。
2. **診療録の情報量**：没入感のため A・E・F に各10件前後の記録を用意する想定。データ作成ボリュームの承認。
3. **タブ数**：10タブで確定（前 08 設計書の4タブ案から、本コンセプトに合わせ10タブへ更新）。
4. **08 設計書との関係**：本 Blueprint 承認後、`08_Compass_Chart.md` を「シミュレーター前提・10タブ」に追従更新する。
