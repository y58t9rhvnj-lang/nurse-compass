## 5. 優先順位

1. **最優先**: 回帰防止の仕組み（flag ガード / 等価性テスト） … 何より先に土台化。
2. **高**: 収集(E1) → 整理土台(E2) → 関連づけ(E4) → 言語化(E6)（学習の背骨）。
3. **中**: 分類(E3) / 見極め(E5)。
4. **後**: 看護課題・Coach 連携(E7)、進捗・提出・教員閲覧（保留項目）。

## 6. 推奨実装順

```
V2-0(設計) → V2-1(土台/収集) → V2-3(関連づけ) → V2-4(言語化)
          → V2-2(分類) → V2-5(見極め/課題) → V2-6(仕上げ)
```

理由: 「収集→関連づけ→言語化」を最短で通し、**学習の芯を早期に体験可能**にする。分類・見極めは芯が通ってから精緻化する。

## 7. 講義後に確定する項目（このフェーズでは決めない）

- 情報整理ノートの配置（IA: A案/B案/C案）
- 情報カードの分類方法（自由文字列 / 定義済みカテゴリ）
- ドラッグ&ドロップの有無（iPad Safari 安定性次第）

- Compass Coach の介入タイミング（能動 / 学生が呼ぶ時のみ）
- 課題完了条件
- 学生へのフィードバック表示
- 進捗表示
- 提出機能
- 教員閲覧機能

## 8. 見積り前提・リスク

- iPad Safari の D&D・スクロール・タップ（`docs/adr/001`）が最大の技術リスク。
- localStorage 容量（カード大量時）— 上限監視と失敗ハンドリングを土台で担保。
- 教育方針（思考の代行禁止）と UI 利便性のトレードオフ — 仕様確定は講義観察に依存。
