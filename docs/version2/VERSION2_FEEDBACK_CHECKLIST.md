# VERSION2_FEEDBACK_CHECKLIST — 講義フィードバック観察チェックリスト

> 目的: 次回講義（Version1 使用）で学生の実際の学びを観察し、**Version2 仕様の確定材料**を集める。
> このチェックリストは「Version2 の保留項目を、どの観察結果で決めるか」を紐づける。

## 1. 講義中に観察する点（全体）

- [ ] 学生は面接で必要な情報を引き出せているか
- [ ] 面接とカルテを行き来しているか（片方に偏っていないか）
- [ ] 集めた情報を自分なりに整理しようとする行動が自然に起きるか
- [ ] 「正解探し」に陥っていないか（自分の言葉で考えているか）
- [ ] つまずいたとき、何を求めるか（ヒント / 分類の枠 / 具体例）

## 2. 学生が迷った箇所

- [ ] どの操作で手が止まったか（面接 / カルテ / メモ）
- [ ] 用語で戸惑った箇所（例: 「収集」「整理」「関連づけ」）
- [ ] 情報が多すぎて整理に着手できない場面はあったか
- [ ] 「分類」と「関連づけ」の違いが伝わっていたか

## 3. 電子カルテの閲覧タイミング

- [ ] 面接前に見る / 面接後に見る / 並行して見る、のどれが多いか
- [ ] よく開くタブはどれか（診療録 / 看護記録 / フローシート / 処方 …）
- [ ] カルテの情報を面接内容と結び付けられていたか
- [ ] カルテ内で迷子になっていないか（タブ移動の様子）

## 4. 患者会話の利用状況

- [ ] 何往復くらい会話したか（浅い / 深い）
- [ ] 話題が広がったか、行き詰まったか
- [ ] 患者の言葉を根拠として使えていたか
- [ ] 会話履歴を後から見返していたか

## 5. Compass Coach の使用状況

- [ ] Coach をどのタイミングで使ったか（能動的に呼ぶ / 出たら見る）
- [ ] 問い返しが役立っていたか、逆に戸惑わせていないか
- [ ] Coach に「答え」を求める傾向はあったか（→ V2 の介入方針判断に直結）
- [ ] Coach が出るタイミングは早すぎ/遅すぎないか

## 6. 情報整理で困った点（V2 中核の判断材料）

- [ ] 情報を「どう分ければよいか」で困ったか（→ 分類方式 A/B の判断）
- [ ] 束ねる操作があれば使いたいと感じたか（→ D&D 有無の判断）
- [ ] 全体像を「自分の言葉で書く」ことに抵抗はあったか（→ 言語化支援の設計）
- [ ] 重要度をつけたいニーズはあったか（→ 見極め機能の判断）

## 7. 学生から出た要望（自由記述で収集）

- [ ] あったらよかった機能
- [ ] 分かりにくかった言葉・画面
- [ ] iPad での操作のしづらさ（タップ / スクロール / 入力）
- [ ] 「もっとこうしたい」という学習上の希望

## 8. 教員として感じた改善点

- [ ] 学習目標に届いていたか
- [ ] つまずきを Coach/導線で救えていたか
- [ ] 説明・オリエンテーションで補った箇所（＝UIで解決すべき箇所）
- [ ] 時間配分（面接 / カルテ / 整理）の実態

## 9. Version2 仕様へ反映する判断基準（観察→意思決定）

| 保留項目 | 決定に使う観察 | A案を採る目安 | B案を採る目安 |
| --- | --- | --- | --- |
| ノート配置 | 4/6 の行き来・迷子 | カルテ併用が少ない→独立ビュー(A) | カルテ併用が多い→サイドパネル(C) |
| 分類方式 | 6 の「どう分けるか困った」 | 困りが少ない→自由文字列(A) | 困りが多い→定義済み枠(B) |
| D&D の有無 | 6・7・iPad操作 | 束ねたい要望が強い＆iPad安定→採用 | 不安定/要望弱→選択式 |
| 自動分類 | 6・思考の代行懸念 | 原則採用しない | （教育方針上、慎重） |
| Coach 介入 | 5 の使い方 | 答えを求めがち→能動介入は抑制 | 呼ばない→軽い能動提示 |
| 完了条件 | 8 の到達度 | 全体像1件で区切り | 看護課題1件で区切り |
| 進捗/提出/教員閲覧 | 7・8 の要望 | 要望強→検討着手 | 要望弱→保留継続 |
