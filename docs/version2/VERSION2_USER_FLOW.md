# VERSION2_USER_FLOW — 想定ユーザーフロー（案）

> ステータス: **設計案**。導線の細部（配置・導入タイミング）は講義後に確定。

対象ユーザー: 看護学生（精神看護学実習の事前学習）。主端末は iPad / PC。

## 1. 全体像（学習の一連の流れ）

```
[学習開始] → [患者面接] → [電子カルテ確認] → [情報整理] → [関連づけ] → [患者理解の言語化] → [看護課題へ]
     ↑___________________ Compass Coach が問い返しで随伴（各段階）___________________↑
```

各段階は一方向ではなく **往復可能**。学生は面接↔カルテ↔整理ノートを自由に行き来する。

## 2. 段階ごとの流れ

### (0) 学習開始
- 病棟ホーム → 受け持ち患者（A/E/F）を選ぶ → 患者トップ。
- 課題シート（`FirstAssignmentSheet`）で本日の目標・観察ポイントを確認（V1既存）。
- **V2差分**: 「この患者の情報を整理する」入口が（flag on 時のみ）現れる。**既定は非表示**。

### (1) 患者面接（V1既存を維持）
- 患者と対話し、必要な情報を引き出す。
- 患者発言・自分の観察を **情報カードとして収集**（`collection` flag on 時）。
  - 収集は「発言を保存する」だけで、**意味づけはしない**（意味づけは後段）。
- Compass Coach は面接中、答えではなく **次の問い** を示唆する（V1挙動を維持）。

### (2) 電子カルテ確認（V1既存を維持）
- 診療録・看護記録・フローシート・処方・検査・生活歴・4帳票などを閲覧。
- 面接で得た情報を **カルテで裏づける／広げる**。
- **V2差分**: カルテ上の記載も情報カードとして収集できる（flag on 時）。出所（`sourceReference`）を保持。

### (3) 情報整理（V2 中核・flag on 時）
- 収集した情報カードを一覧し、**分類（カテゴリ/視点）** を付ける。
  - 分類方式（自由ラベル / 定義済みカテゴリ / ゴードン等の枠組み）は **保留（A案/B案）**。
- 重要な情報を **見極める**（並び替え・重要度）。方式は **保留**。
- ここでも Coach は「なぜそれが重要？」と **問い返す**（答えは出さない）。

### (4) 関連づけ（V2 中核・flag on 時）
- 複数の情報カードを束ねて「整理された情報（`OrganizedInformation`）」を作る。
  - 例: 「夜間の幻聴」＋「頓服使用」＋「日中の傾眠」→『睡眠と幻聴の関連』。
- 束ね方（ドラッグ&ドロップ / 選択式 / タグ）は **保留（A案/B案）**。
- `sourceDataIds` で元カードへの参照を保持（出所に必ず戻れる）。

### (5) 患者理解の言語化（V2 中核・flag on 時）
- 学生が **自分の言葉** で患者の全体像を記述する（`OrganizedInformation.title/content`）。
- 改稿は **revision 履歴** として残る（考えの変化を可視化。破壊的上書きをしない）。
- **自動生成はしない**。テンプレの穴埋めではなく、学生の記述を主とする。

### (6) 看護課題へつなげる（V2 発展・flag on 時）
- 言語化した全体像から、看護上の課題・気がかりへ橋渡し。
- Coach は「その理解から、次に確かめたいことは？」と **問いで誘導**。
- 課題の完了条件・提出の有無は **保留**（このフェーズでは決めない）。

## 3. Compass Coach との関係（全段階共通）

- 役割は **伴走者**。答え・分類・アセスメントを **代行しない**。
- 出力は基本 **問い返し**（例: 「その情報は、どの訴えと関係しそう？」）。
- 介入タイミング（能動的に出す / 学生が呼ぶ時のみ）は **保留（A案/B案）**。
- V1 の面接 Coach 挙動は **変更しない**。整理段階の Coach は別導線として設計する。

## 4. 学習完了までの流れ（案）

```
面接で情報を集める
   ↓（収集）
カルテで裏づける・広げる
   ↓（収集）
情報カードを分類する
   ↓（見極め）
重要な情報を関連づける
   ↓（言語化）
患者の全体像を自分の言葉で書く
   ↓（問い返し）
看護上の課題・次の問いへ
```

- 「完了」の定義（どこまでで一区切りか）は **保留**。
  - A案: 全体像を1つ書き上げたら一区切り。
  - B案: 看護課題を1つ言語化したら一区切り。
- 進捗表示・提出・フィードバック表示は **保留**（`VERSION2_TASK_BREAKDOWN.md` 参照）。

## 5. エッジケース / 迷いどころ（講義で観察したい点）

- 収集した情報が多すぎて整理に着手できない。
- 「分類」と「関連づけ」の違いが分からない。
- カルテと面接の情報を **どう結ぶか** が分からない。
- 自分の言葉で書くのをためらう（正解探しに陥る）。

> 具体的な観察項目は `VERSION2_FEEDBACK_CHECKLIST.md` に集約。
