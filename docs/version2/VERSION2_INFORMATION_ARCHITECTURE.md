# VERSION2_INFORMATION_ARCHITECTURE — 情報アーキテクチャ（案）

> ステータス: **設計案**。ノート配置・遷移方式は講義後に確定（複数案を併記）。

## 1. 現行（Version1）の構成（前提・不変）

- `AppShell` が上位状態を管理: `activeView: "ward" | "patient" | "chart"`、`selectedId`（患者）。
- 左: `SideNav`（病棟ホーム/患者トップ/電子カルテ/情報BOX/申し送り/…）。
- 中央 + 右ペイン構成。患者トップは「その人を知る」「回復に向けて」「気づきメモ」ゾーン。
- 電子カルテのタブ（`ChartTabId`）:
  `診療録 / 患者情報 / 生活歴 / エピソード / 医療サマリー / 看護記録 / OT / PSW / フローシート / 検査 / 処方 / 書類`。
- 患者面接画面: 中央=会話、右=Compass Coach パネル。

> Version2 でもこの骨格は壊さない。追加は **flag で隔離** し、off 時は V1 と同一表示。

## 2. Version2 で追加する情報空間（候補）

「情報整理ノート（Clinical Thinking Workspace）」を **第4のビュー** として追加する案を基本線とする。

- `activeView` に `"workspace"`（仮）を追加（flag on 時のみナビ表示）。
- 構成要素:
  - **情報カード一覧**（収集済みカード / `InformationCard`）
  - **整理エリア**（分類・関連づけ / `OrganizedInformation`）
  - **言語化エリア**（全体像を自分の言葉で）
  - **Coach パネル**（問い返し）

## 3. 情報整理ノートの位置（保留：A案/B案）

### A案: 独立ビュー（SideNav に「情報整理ノート」を追加）
- 面接・カルテと **並列** の第4ビュー。
- 長所: 作業空間が広い（iPad 全画面）。整理に集中できる。カルテ/面接と往復しやすい。
- 短所: 画面移動が増える。カルテを見ながら整理しにくい（別画面）。

### B案: 患者トップ内の第4ゾーン（気づきメモの下に増設）
- 既存の患者トップに埋め込む。
- 長所: 患者理解の文脈に近い。導線が最短。
- 短所: 縦に長くなりスクロール過多。カード数が増えると破綻しやすい。

### C案（折衷）: カルテ横のサイドパネルとして開閉
- 電子カルテを見ながら右からノートをスライド表示。
- 長所: カルテ↔整理が同一画面。裏づけしながら整理できる。
- 短所: iPad 幅では窮屈。実装が最も重い。

> 推奨初期値: **A案（独立ビュー）** を骨格にしつつ、C案の「カルテからカードを送る」導線を段階的に検討。ただし **講義後に確定**。

## 4. タブ構成（整理ノート内・案）

整理ノート内は段階に沿った内部タブ/セクション構成を候補とする（呼称は仮）。

| セクション | 役割 | 対応データ |
| --- | --- | --- |
| 集めた情報 | 収集カード一覧・分類 | `InformationCard[]` |
| つなげる | 関連づけ・束ね | `OrganizedInformation`（`sourceDataIds`） |
| 全体像 | 自分の言葉で言語化 | `OrganizedInformation.content`（revision） |
| ふりかえり | 看護課題・次の問い | Coach 連携（保留） |

> セクションを「タブ」にするか「縦積み」にするかは iPad 実機で要検証（保留）。

## 5. 電子カルテとの行き来

- カルテ上の記載 → 情報カード化（`sourceReference` に `tab` / `recordId` / `date` 等を保持）。
- 情報カード → 出所へ戻る（`resourceToNav` / `ChartFocus` と対応づけ。V1 の関連情報導線を再利用）。
- 原則: **カードは必ず出所に戻れる**（学生が根拠を確認できる）。

## 6. 患者会話との行き来

- 患者発言 → 情報カード化（`sourceType: "patient_conversation"` / `entryId` を参照）。
- 会話履歴は患者別に永続化済み（V1: `compass:v1:patient-conversation:<patientId>`）。
- 整理ノートから会話の該当発言へ戻れる導線を検討（保留）。

## 7. PC / iPad での配置案

### PC（横長・>1024px）
- 3カラム: 左=SideNav / 中央=作業空間（カード・整理） / 右=Coach。
- カルテ併用時は「カルテ全幅 → ノートは独立ビュー切替」を基本（A案）。

### iPad（横 1024–1366 / 縦 768–1024）
- 横向き推奨。2カラム（作業空間 + Coach）＋ SideNav は折りたたみ。
- 縦向きでは Coach を下部シート化する案（保留）。
- **タップ標的は 44px 以上**（既存方針を踏襲。`docs/adr/001-iPad-Safari-Tap-Issue.md` を順守）。
- ドラッグ&ドロップは iPad Safari で不安定になりやすいため、**採用可否を保留**（代替: 選択式の割り当て）。

### スマートフォン
- 主対象外。最低限クラッシュしない・閲覧はできる、を下限とする（レイアウト最適化はしない）。

## 9. 回帰防止（IA 観点）

- `activeView` への追加値は flag ガード下でのみ有効化。off 時は既存3ビューのみ。
- SideNav の項目追加は flag on 時のみ描画（V1 のナビ項目・順序は不変）。
- 既存タブ（`ChartTabId`）は追加・削除・改称しない。
