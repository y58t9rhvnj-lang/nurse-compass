# Form3 AI Evaluation Policy（Compass）

Status: **仕様固定（教育政策・評価原則）**  
Scope: Version 2.2 における **様式3（Form3）段階**の AI 評価原則  
`compass_policy_version`（実装）: **2026.5**（Form2 の **2026.4** とは別。教育本文の再解釈ではない）  
対応ドキュメント:

- Form2 政策正本（変更しない）: `02_ai_evaluation_policy.md`（`compass_policy_version` **2026.4** / `rubric_version` **3**）
- パッケージ仕様: `01_ai_evaluation_package_spec.md`
- 成果物レジストリ: `../21_assessment_artifact_registry.md`
- staging / import / adoption / batch: `03`〜`06`
- アーキテクチャ: `architecture.md`

本書は Form3 の教育設計を、今後の AI 評価実装における **Form3 側の正本**として固定する。  
**Form2 向け `02_ai_evaluation_policy.md` を置き換えない。** マイルストーン種別・評価段階に応じて適用する政策を選択する。

| 項目 | Form2（`02` / 2026.4） | Form3（本書） |
|------|------------------------|---------------|
| 教育的焦点 | 個々の情報に意味を与え、患者理解を**始める** | 意味をもった情報を整理し、関連づけ・解釈・予測し、**必要な看護へつなげる** |

## 1. Form3 の教育的位置づけ

### Form2

「個々の情報に意味を与え、患者理解を始める」

### Form3

「意味をもった情報をゴードンの 11 の機能的健康パターンというレンズで整理し、情報同士を関連づけ、患者に現在起こっていること・今後起こり得ることを考え、必要な看護へつなげる」

Form3 は **単なる 11 パターンへの情報分類課題ではない。**

Compass 全体として、AI 評価は完成物の採点装置ではなく、学生が患者理解を更新し続ける思考過程を支援する手段である（§11）。教員の確定評価を代替しない。

## 2. 上位評価軸

Form3 の上位評価軸は次の **3 つ**である。  
これらは **新しい rubric key ではない。** 既存 7 key で観察する（§4）。

### ① 情報整理

ゴードンの 11 の機能的健康パターンを、「正しい箱に分類するための枠」ではなく **「患者を見るためのレンズ」** として使用する。

**評価するもの**

- 患者を考えるために必要な情報を拾えているか
- 情報を適切に整理しようとしているか

**評価しないもの**

- 情報量の多さ
- パターン分類の完全一致
- 深い解釈を①だけで要求すること

同じ情報が複数パターンに意味を持つことを **許容する。**

### ② 関連づけ・解釈・予測

**Form3 の中心評価領域。**

複数情報を関連づけ、次を考えているかを評価する。

- 患者に現在何が起きているのか
- なぜ起きている可能性があるのか
- 今後何が起こり得るのか

単に複数情報が同じ文章内に存在するだけでは「関連づけ」と判定しない。

一つの解釈への固定よりも、次に気づき、新しい情報によって患者理解を更新できることを **高く評価する。**

- 別の可能性
- 不足情報
- 不確実性
- 確認すべき情報

「分からない」「判断には追加情報が必要」と適切に認識することも、臨床推論として評価する。

### ③ 必要な看護への展開

②で捉えた患者の状態・今後の可能性を根拠として、その患者に **必要な看護を考えているか** を評価する。

**重要**

- 看護行為や教科書的看護が記載されているだけでは高評価にしない。
- 評価するのは次の **論理的接続** である。

```text
患者情報
  → 関連づけ
  → 解釈
  → 現在/今後の判断
  → 必要な看護
```

Form2 政策の「看護を評価対象にしない」と混同しないこと（§0・§7）。

## 3. 5 段階の到達像

共通のスコア尺度（1〜5）を用いるが、**Form3 における到達の意味**は次のとおりとする。  
文章量・専門用語の量・看護行為の数では評価しない。

| 水準 | 到達像 |
|------|--------|
| **1** | 提出内容から思考過程を確認する材料がほぼない。能力がないとは断定しない。「提出された記述からは確認できない」と表現する。 |
| **2** | 情報整理にとどまる。情報量が多くても、情報同士の関連づけが確認できなければそれだけで高評価にしない。 |
| **3** | 複数情報を関連づけ、患者に現在起こっていることを可能性として説明できる。**Form3 の基本的な合格水準。** |
| **4** | 現在の患者理解から、今後起こり得ることや必要な看護へ根拠をもって展開している。 |
| **5** | 別可能性・不足情報・不確実性を認識し、追加情報によって患者理解を更新しながら、必要な看護について考えることができる。 |

## 4. 7 rubric との関係

- 既存 7 `rubric_key` は **変更しない。**
- 上位三軸を新しい rubric key として **追加しない。**
- 7 rubric は、上位三軸の達成状況を観察する **「下位レンズ」** として扱う。
- **7 rubric の単純平均で総合評価を決定しない。**

### Form3 における各 key の意味づけ

| rubric_key | 主に照らす上位軸 | Form3 での観察焦点 |
|------------|------------------|-------------------|
| `information_gathering` | ① | 11 パターンをレンズとして必要情報を整理しているか |
| `relating_information` | ② | 複数情報を関連づけているか（併記だけでは不足） |
| `interpretation_analysis` | ② | 現在起きていること・意味・可能性を考えているか |
| `clarity_of_evidence` | ② | 解釈・判断が提出された患者情報に基づいているか |
| `awareness_of_gaps` | ②および深化 | 不足情報・別可能性・不確実性に気づいているか |
| `patient_understanding` | ② | 関連づけた情報から患者の状態を捉えているか |
| `overall_integration` | ③および深化 | 患者理解から必要な看護へ論理的に展開し、必要に応じて理解を更新できているか |

ラベル（日本語）は既存アプリ定数に従う（情報収集 / 情報の関連づけ / 解釈・分析 / 根拠の明確さ / 不足情報への気づき / 患者理解 / 全体統合）。

## 5. 現行 Form3 フィールドの扱い（V2.2）

V2.2 では新しい「必要な看護」専用フィールドを **追加しない。**

### 主評価対象（Final）

- `finalForm.<patternKey>.informationSO`
- `finalForm.<patternKey>.interpretationAnalysisCareNeed`

`interpretationAnalysisCareNeed` は UI 上「解釈・分析・援助の必要性」が **同一フィールド** に存在する。  
AI は文章から次の論理的接続を読む。

```text
解釈 → 判断 → 援助の必要性（必要な看護への展開）
```

フィールドが分かれていないことを理由に、③を評価対象外にしない。  
同時に、援助・看護の **羅列だけ**を③の高到達としない（§2・§3）。

### 補助証拠（Cards）

- Information Cards / Assessment Cards は、思考過程を **補助的に確認する材料** とする。
- **Final = 主評価対象**
- **Cards = 補助証拠**

カード枚数そのものでは加点しない。

## 6. progress / complete

| milestone 種別（例） | 位置づけ | 評価の扱い |
|----------------------|----------|------------|
| `form3_progress` | 形成評価 | 学生が現在どこまで考えられていて、次に何を考えるとよいかを示す。未完成であること自体を過度に減点しない。 |
| `form3_complete` | 総括寄り評価 | ①情報整理 → ②関連づけ・解釈・予測 → ③必要な看護 → 深化、という到達像を評価する。 |

## 7. AI Compass Coach

AI は答えを書かない。学生が現在いる思考段階の **「一つ先」** を問う。

### 許可

- 学生が記載した看護の根拠を問い返す
- 必要な看護を考えるための問いを返す
- 不足情報や別可能性を考えるよう促す

### 禁止

- AI が看護計画を完成させる
- AI が具体的な援助・観察項目の正解一覧を提示する
- 教員の模範解答を学生へ転記する
- Gold Standard の不足項目を学生フィードバックとして提示する

### Form2 政策との区別（再掲）

| | Form2（2026.4） | Form3（本書） |
|--|-----------------|---------------|
| 学生が必要な看護を考えられているか | 評価対象外 | **評価対象** |
| AI が必要な看護・計画・援助一覧を答えること | 禁止 | **禁止（同じ）** |

## 8. 11 パターン横断評価

- 11 パターンすべてに同じ深さを要求しない。
- 患者理解上重要なパターンで深く考えられていることを評価する。
- Final 等の既存データを横断して、パターンを越えた患者理解が始まっているかを見る。
- Form3 段階では **「関連図が完成している」とは評価しない。**

位置づけ:

```text
Form3     → パターンを越えた患者理解が始まる
関連図    → その関係を可視化・統合する
```

関連図 artifact の schema・実装は本書の対象外（§12）。

---

## 9. Gold Standard

次は Form2 政策（`02` §5）と **同趣旨**で Form3 にも適用する。

- Gold Standard は模範解答との一致判定に使用しない。
- Gold にある内容を書いていないことを理由に減点しない。
- Gold にない学生の解釈でも、提出された患者情報から妥当な推論であれば評価する。
- Gold は教員・AI 側の比較・観察材料（主に `teacher_observation`）。
- Gold との差分をそのまま学生フィードバックへ出さない。
- 学生フィードバック草案の作成に Gold を使わない。

---

## 10. 評価上の禁止事項

以下を禁止する。

1. 文章量による加点  
2. 専門用語数による加点  
3. 情報カード数による加点  
4. 看護行為数による加点  
5. Gold との一致率による採点  
6. 11 パターンすべてを同一深度で要求  
7. 一つの解釈を唯一の正解として扱う  
8. 空欄から能力不足を断定  
9. 7 rubric の単純平均による総合評価  
10. AI による看護計画の完成  
11. AI による具体的援助・観察項目の正解一覧提示  
12. Gold / 教員模範の学生への転記  
13. 提出にない事実の推測補完  
14. AI 結果の学生への自動返却（共通アーキテクチャ）  
15. `private_note` / `student_notes` の AI 送信・学生出力への混入（共通）

## 11. 患者理解の循環

Form3 評価は一本道として扱わない。

```text
情報整理
  → 関連づけ
  → 解釈
  → 現在の理解
  → 今後の可能性
  → 必要な看護
  → 不足情報・別可能性への気づき
  → 新しい情報収集
  → 患者理解の更新
```

Nurse Compass における評価の目的は、完成した文章の採点ではなく、**学生が患者理解を更新し続ける思考過程を支援すること**である。
