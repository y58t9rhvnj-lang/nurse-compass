# Compass Version2 Workspace Mockups（画面仕様書）

- ステータス: **設計のみ**（実装前）。本書ではアプリコード・DB を変更しない。
- 設計基準: `docs/version2/13_ui_architecture.md`（Compass Workspace Design System / CWDS）。本書はその原則を**実際の画面仕様**へ落とし込む。
- 関連: 学習設計 `15_learning_design.md`、Learning Layer `14_learning_layer_architecture.md`。
- 禁止事項（本フェーズ）: コード変更・DB 変更・migration・commit・push は行わない。

---

## 1. Purpose

本書は Compass Version2 の **Workspace UI 仕様書**である。学習体験を「実装」ではなく「画面仕様」として可視化し、各学習フェーズ専用 Workspace のレイアウト・責務・支援内容を確定する。

**対象デバイス**

- **Desktop**（PC・横長）
- **iPad Landscape**（iPad 横向き）

いずれも 3 カラム（左＝患者情報 ／ 中央＝フェーズ主役 ／ 右＝Learning Inspector）を基本とし、幅に応じて Inspector の表示形態を切り替える（§7）。

---

## 2. Learning Progression（学習フロー全体）

Compass Version2 は学習フェーズごとに専用 Workspace を持つ。全体フローは次のとおり。

```
        電子カルテ
            │
        患者との会話
            │
            ▼
【様式2 Workspace】 様式2
            │
            ▼
        Coach による整理支援
            │
            ▼
        Compass Note
            │
            ▼
        患者像を形成
────────────────────────────
【様式3 Workspace】 様式3
            │
            ▼
        Evidence
            │
            ▼
        患者理解
            │
            ▼
        看護問題
────────────────────────────
【関連図 Workspace】 関連図
            │
            ▼
        関連図完成
            │
            ▼
        看護計画
```

各フェーズで「学生が何を考えるのか」「AI（Coach）は何を支援するのか」を整理する。

### 2.1 様式2 Workspace フェーズ（情報整理）

- **学生が考えること**: 電子カルテと会話から得た情報を「様式2 の枠組み」で整理・構造化する。何がわかっていて、何がまだ足りないのかを把握する。気付き・疑問・仮説を Compass Note に残す。
- **AI（Coach）の支援**: 情報不足・整理漏れ・確認事項の気づきを促すのみ。アセスメント・診断・様式2 の文面は書かない（答えを提示しない）。
- **アウトプット**: 整理された様式2 と、様式3 へつなぐ Compass Note（患者像の芽）。

### 2.2 様式3 Workspace フェーズ（患者理解・臨床推論）

- **学生が考えること**: Compass Note を起点に、根拠となる Evidence を選び、患者理解を深め、看護問題へと発展させる。事実（Evidence）と解釈（理解）を分けて考える。
- **AI（Coach）の支援**: 根拠の不足、理解の飛躍、拾えていない情報への気づきを促す。看護問題そのものは提示しない。
- **アウトプット**: Evidence に裏づけられた患者理解と看護問題。

### 2.3 関連図 Workspace フェーズ（思考の可視化 → 看護計画）

- **学生が考えること**: Evidence・Compass Note・Story を Canvas 上で関連づけ、患者像と看護問題のつながりを図として構成する。関連図の完成から看護計画へ展開する。
- **AI（Coach）の支援**: つながりの不足・孤立したノード・未整理の関係への気づきを促す。関連図を自動生成しない。
- **アウトプット**: 関連図の完成、そして看護計画。

> フェーズが進むごとに主役が変わる（様式2 → Evidence → Canvas）。学生の思考段階に合わせて UI が変化する（§9）。

## 3. Form2 Workspace（様式2 Workspace）

**目的: 情報整理**

### レイアウト

```
┌──────────────┬────────────────────────────┬──────────────┐
│              │                            │              │
│ 患者トップ    │         様式2              │ Learning     │
│              │                            │ Inspector    │
│ カルテ        │                            │              │
│ 会話          │                            │ Coach        │
│              │                            │ Compass Note │
└──────────────┴────────────────────────────┴──────────────┘
```

### 左ペイン（患者情報）

- 患者トップ（起点）
- 電子カルテ
- 患者との会話

一次情報の参照領域。ここから中央の様式2 を書くための材料を確認する。

### 中央（主役）

- **様式2 のみ**。他の要素で中央を割らない。保存の正は Supabase。

### 右ペイン（Learning Inspector）

タブ構成:

- **Coach**
- **Compass Note**

### 学習目標

学生はこのフェーズでは **情報整理** と **情報の構造化** のみを行う（患者理解・看護問題の結論づけは次フェーズ）。

### Coach（このフェーズ）

支援内容は次の 3 点のみ:

- 情報不足
- 整理漏れ
- 確認事項

**答えは提示しない**（診断・アセスメント・様式2 の文面を書かない）。

### Compass Note（このフェーズ）

- **保存する内容**: 気付き ／ 疑問 ／ 仮説 ／ 後で考えたいこと
- **保存しない内容**: 電子カルテの写し ／ 様式2 の下書き

Compass Note は様式2 を書くための下書きではなく、様式3 への思考をつなぐ記録である。

## 4. Form3 Workspace（様式3 Workspace）

**目的: 患者理解・臨床推論**

### レイアウト

```
┌──────────────┬────────────────────────────┬──────────────┐
│              │                            │              │
│ 患者トップ    │         様式3              │ Learning     │
│              │                            │ Inspector    │
│              │                            │              │
│              │                            │ Evidence     │
│              │                            │ Compass Note │
│              │                            │ Coach        │
└──────────────┴────────────────────────────┴──────────────┘
```

### Evidence が主役

このフェーズでは **Evidence が主役**になる。様式2 Workspace が「情報を枠に整理する」場だったのに対し、様式3 Workspace は「根拠（Evidence）に基づいて患者を理解し、看護問題へ発展させる」場である。中央の様式3 記述は、右ペインの Evidence を参照しながら進める。Learning Inspector のタブ先頭に Evidence を置き、思考の中心であることを示す。

### 思考の流れ

```
Compass Note
    ↓
Evidence
    ↓
患者理解
    ↓
看護問題
```

- **Compass Note → Evidence**: 様式2 フェーズで残した気付き・疑問・仮説を見直し、根拠になる情報を Evidence として明示的に選ぶ（自動変換はしない）。
- **Evidence → 患者理解**: 選んだ Evidence を突き合わせ、事実が示す意味を考える。事実（Evidence）と解釈（理解）を分ける。
- **患者理解 → 看護問題**: 患者理解を根拠づけながら、看護問題を言語化する。Coach は不足や飛躍への気づきを促すが、看護問題そのものは提示しない。

## 5. Related Map Workspace（関連図 Workspace）

**目的: 思考を可視化する**

### レイアウト

```
┌──────────────┬────────────────────────────┬──────────────┐
│              │                            │              │
│ 患者トップ    │     Related Map Canvas     │ Learning     │
│              │                            │ Inspector    │
│              │                            │              │
│              │                            │ Evidence     │
│              │                            │ Compass Note │
│              │                            │ Story        │
│              │                            │ Coach        │
└──────────────┴────────────────────────────┴──────────────┘
```

### Canvas が主役

中央は **Related Map Canvas**（ノードとつながりを配置する図の作業空間）で、これが主役。学生は右ペインの素材（Evidence／Compass Note／Story）を Canvas に引き込み、患者像・看護問題のつながりを図として構成する。

- **Evidence**: 事実の根拠ノード。
- **Compass Note**: 気付き・疑問・仮説のノード。
- **Story**: 患者の物語・患者像の文脈。
- **Coach**: つながりの不足・孤立ノード・未整理の関係への気づきを促す（図は自動生成しない）。

Canvas は CWDS の視覚言語（静か・読みやすい）に従い、完成後は看護計画へ展開する。

## 6. Learning Inspector（Workspace 共通思想）

Learning Inspector は全 Workspace 共通の右側支援領域。次を明文化する。

- **器は共通**: 開閉・レイアウト（Desktop 右サイドパネル／iPad 下シート）・オーバーレイ・スクロール・`no-print`・状態保持のみを担い、ドメイン知識を持たない。
- **Workspace が変われば表示内容だけ変わる**: 器は同じで、表示する Panel 集合（タブ）だけを切り替える。
  - 様式2 Workspace: Coach ／ Compass Note
  - 様式3 Workspace: Evidence ／ Compass Note ／ Coach
  - 関連図 Workspace: Evidence ／ Compass Note ／ Story ／ Coach
- **Workspace の主役を邪魔しない**: 中央（様式2／様式3／Canvas）の視認性・文脈を奪わない。情報階層上は常に最下位（補助）。
- **必要時のみ開く支援領域**: 常時展開を強制しない。閉じれば中央の作業に戻り、開閉で状態を失わせない。

## 7. Responsive Design

3 カラム（左＝患者情報／中央＝主役／右＝Learning Inspector）を基本に、幅で Inspector の形態を変える。

### Desktop

- **Inspector 開**: 3 カラム横並び。中央が最大幅を保ち主役であり続ける。目安比率 **左 22% / 中央 53% / 右 25%**。Inspector 内のみスクロール、中央の高さは増やさない。
- **Inspector 閉**: 2 カラム。中央が拡張して主役性が増す。目安比率 **左 24% / 中央 76%**。右端に Inspector を開くトグルを常設。

### iPad Landscape

- **Inspector 開**: 横幅に余裕があれば 3 カラム維持（目安 **左 24% / 中央 50% / 右 26%**）。狭い場合は Inspector を**右からの下シート／オーバーレイ**に切り替え、中央・左を隠さない（V1 `CollectionDialog` のレスポンシブ挙動を踏襲）。
- **Inspector 閉**: 2 カラム（目安 **左 26% / 中央 74%**）。Inspector はトグルで必要時のみ呼び出す。

> 比率は目安。いずれのデバイス・状態でも「中央＝主役」を崩さず、Inspector 開閉で中央の内容・スクロール・入力を破棄しない。

## 8. Navigation

Workspace（様式2 ↔ 様式3 ↔ 関連図）を切り替えても、次を保持する。

- **患者**: 選択患者・受け持ち文脈。
- **文脈**: 各 Workspace の作業状態（開いている情報・参照中の Evidence 等）。
- **スクロール位置**: 中央・左・Inspector 各領域のスクロール。
- **入力内容**: 様式2／様式3 の記述、Compass Note の編集中テキスト、Canvas の配置。
- **Inspector 状態**: 開閉状態・アクティブタブ。

フェーズ遷移は「別ページへの離脱」ではなく学習段階の切替として扱い、上記を失わせない。受け持ち患者のみが Learning Layer（様式2／様式3／関連図・Evidence・Compass Note）の対象（`14`/`15` 準拠）。

## 9. Design Principles

本 Workspace 設計の原則:

- **Workspace は学習フェーズごとに存在する**（様式2／様式3／関連図。単一画面にしない）。
- **中央が常に主役**（様式2 → Evidence を伴う様式3 → Canvas）。左（患者情報）と右（Inspector）は主役を支える。
- **Learning Inspector は支援役**（器は共通・表示内容のみ変わる・必要時のみ開く・主役を邪魔しない）。
- **AI は思考を代行しない**（Coach は情報不足・整理漏れ・確認事項・つながりの気づきのみ。答え・診断・様式・関連図を書かない）。
- **学生の思考段階に合わせて UI が変化する**（情報整理 → 臨床推論 → 可視化で、主役とツールが切り替わる）。
- **文脈維持**（フェーズ遷移・Inspector 開閉で患者・入力・状態を失わせない）。
- **CWDS 準拠**（`13_ui_architecture.md` の哲学・視覚言語・Non-goals をすべての Workspace が継承する）。
